## 6. 原文 vs 生成文の比較

### 6.1 主な違い

| 項目 | 原文 | 生成文 |
|------|------|--------|
| 仮名遣い | 旧仮名遣い(「ゐた」「やう」) | 現代仮名遣い+旧仮名遣いの混在 |
| 漢字字体 | 旧字体(「廣い」「圓柱」「佛像」) | 新字体(「広い」「円柱」「仏像」) |
| 完全性 | 完全な原文(約8,000文字) | 不完全・生成エラーあり(約3,800文字) |
| セリフの位置 | 原文でも地の文と同行 | 同様に地の文と同行 |
| 読み仮名 | なし | 一部に付与済み |

### 6.2 整形の目標

**原文の場合**:
- 旧仮名遣い・旧字体を**保持**しながら整形
- 青空文庫形式として既に高品質なため、最小限の整形で十分

**生成文の場合**:
- 現代仮名遣いへの統一も検討可能
- 生成エラー(25行目)の修正または削除
- より積極的な整形が必要

## 7. 推奨される処理順序

### 7.1 原文の処理順序

1. **行番号と矢印の削除** (前処理)
   - 正規表現: `^\d+→` を削除

2. **フェーズ1: 基本整形**
   - 約物の統一(必要最小限)

3. **フェーズ2: 段落処理**
   - 全段落に字下げを追加

4. **フェーズ3: セリフ処理**
   - セリフの改行(8, 9, 10行目など)

5. **品質チェック**
   - 旧仮名遣い・旧字体が保持されているか確認

### 7.2 生成文の処理順序

1. **行番号と矢印の削除** (前処理)

2. **生成エラーの修正** (前処理)
   - 25行目の意味不明な箇所を削除または修正

3. **フェーズ1: 基本整形**
   - 空行の削除(7行目)
   - 約物の統一

4. **フェーズ2: 段落処理**
   - 全段落に字下げを追加

5. **フェーズ3: セリフ処理**
   - セリフの改行(13, 16行目など)

6. **手動レビュー**
   - 読み仮名の追加(必要に応じて)

## 8. 期待される改善効果

### 8.1 可読性の向上
- 段落の視覚的な区別が明確になる
- セリフと地の文の境界が明確になる
- 行番号がなくなり、純粋な小説テキストとして読みやすくなる

### 8.2 縦書きレイアウトへの適合性
- 全角スペースによる字下げが縦書きで正しく表示される
- 約物の統一により、フォントの互換性が向上
- 旧字体・旧仮名遣いも縦書きで美しく表示される

### 8.3 出版品質への適合
- JIS規格に準拠した文字使用
- プロフェッショナルな体裁の実現
- 青空文庫形式としての品質保証

## 9. 実装への推奨事項

### 9.1 両ファイル対応の必要性
整形プログラムは以下の両方に対応すべき:
- **原文**: 旧仮名遣い・旧字体を保持しながら整形
- **生成文**: 現代語としての整形+エラー修正

### 9.2 設定可能な項目
```python
config = {
    'preserve_old_kana': True,  # 旧仮名遣いを保持
    'preserve_old_kanji': True,  # 旧字体を保持
    'remove_line_numbers': True,  # 行番号を削除
    'add_indentation': True,  # 字下げを追加
    'format_dialogues': True,  # セリフを改行
}
```

### 9.3 テストデータとしての活用
- **原文**: 正解データとして活用
- **生成文**: 実際の整形対象として活用
- 両者の比較で品質評価が可能
