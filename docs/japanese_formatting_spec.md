# 縦書き日本語小説 文字データ制作ルール仕様書

本ドキュメントは、縦書き日本語小説のテキストデータを制作する際の標準ルールを定義します。

---

## 1. 文字・エンコーディング規則

### 1.1 使用可能文字の範囲 🔴
- 使用文字はJIS X 0213:2004(JIS2004)およびAdobe-Japan1-6の範囲内に限定する
- **実装難易度**: 高
- **理由**: 文字コードポイントの検証とマッピングテーブルが必要

### 1.2 漢字字形の選択 🟡
- 原則として日本語字形の漢字を使用する
- 固有名詞など原文の字形を尊重すべき場合は、JIS X 0213:2004およびAdobe-Japan1-6の範囲内で表記できる字形を使用する
- 範囲外の文字は日本語字形に置き換える
- **実装難易度**: 中
- **理由**: 字形判定にはある程度のルールベース処理が可能

### 1.3 同形異字の処理 🔴
- Unicode入力の際、同形異字(例:「辻」U+8FBB と「辻」U+FAC1)は日本語正字形(JIS基準)を優先する
- **実装難易度**: 高
- **理由**: IVS(Ideographic Variation Sequence)対応の字形データベースが必要

### 1.4 環境依存文字の排除 🟡
- 環境依存文字・機種依存文字(①②、㈱、旧JIS外字など)は使用しない
- **実装難易度**: 中
- **理由**: 禁止文字リストとUnicode正規化(NFKC)で対応可能

---

## 2. 文字種・約物のルール

### 2.1 半角文字の使用制限 🟡
- 半角文字は原則使用しない
- **例外**:
  - 縦中横で処理する2桁以内の数字 → 半角で記述
  - 欧文(アルファベット複数文字の単語・略語) → 半角で記述
- それ以外の記号・約物はすべて全角で統一する
- **実装難易度**: 中
- **理由**: 数字の桁数判定と欧文判定が必要

**例**:
```
OK: 12時、ABCホテル
NG: 123時、A
```

### 2.2 三点リーダーの統一 🟢
- 三点リーダーは「……」(2個連続)で統一する
- 「...」や「・・・」は使用しない
- **実装難易度**: 低
- **理由**: 単純な文字列置換で対応可能

**変換例**:
```
変換前: そして...彼は消えた
変換後: そして……彼は消えた
```

### 2.3 ダッシュの統一 🟢
- ダッシュは「――」(2個連続)で統一する
- 「―」1個のみや「—」(emダッシュ)は使用しない
- **実装難易度**: 低
- **理由**: 正規表現による置換で対応可能

**変換例**:
```
変換前: 彼は――そう、あの男だった
変換後: 彼は――そう、あの男だった
```

### 2.4 波ダッシュの統一 🟢
- 省略符号の波ダッシュは「〜」を使用する
- 「～」(全角チルダ)は使用しない
- **実装難易度**: 低
- **理由**: 単純な文字列置換で対応可能

**変換例**:
```
変換前: 東京～大阪
変換後: 東京〜大阪
```

## 3. 改行・段落のルール

### 3.1 段落の字下げ 🟡
- 段落の書き出しは全角スペース1字分の字下げを行う
- **実装難易度**: 中
- **理由**: セリフとの判別が必要

**例**:
```
　ある日の暮方である。一人の下人が、羅生門の下で雨やみを待っていた。
```

### 3.2 セリフ・発話の改行処理 🔴
- 登場人物のセリフ・発話の「」は改行して独立した段落として書き出す
- 書き出しに字下げは行わず、かぎかっこを行頭から始める
- **実装難易度**: 高
- **理由**: セリフか固有名詞かの判別に文脈解析が必要

**例**:
```
下人は叫んだ。
「何をしていた。云え」
老婆は震えていた。
```

### 3.3 地の文中の「」の処理 🔴
- 固有名詞・引用・強調など地の文に埋め込まれた「」は改行しない
- **実装難易度**: 高
- **理由**: セリフとの区別に高度な文脈解析が必要

**例**:
```
彼は「羅生門」という小説を読んだ。(改行しない)
```

### 3.4 セリフ後の地の文の改行 🔴
- セリフ・発話の「」が終わった後、地の文が続く場合も改行して新段落とする
- **実装難易度**: 高
- **理由**: セリフと地の文の境界判定が必要

**例**:
```
「何をしていた」
下人は太刀に手をかけた。
```

### 3.5 場面転換の処理 🔴
- 場面転換(時間・場所の変化)は1行空けて区切る
- **実装難易度**: 高
- **理由**: 場面転換の自動検出には高度なNLP技術が必要

**例**:
```
羅生門の下で雨宿りをしていた。

翌朝、京の都は静かだった。
```

### 3.6 段落間の空行 🟢
- 段落間に空行は入れない
- **実装難易度**: 低
- **理由**: 正規表現による削除で対応可能

---

## 4. 会話文のルール

### 4.1 閉じかぎかっこ前の句点 🟢
- セリフ・発話の閉じかぎかっこ「」前の句点(。)の有無は、ソース文章の表記に従い全編で統一する
- **実装難易度**: 低
- **理由**: 原文の表記を保持するため、特別な処理は不要

**例**:
```
「そうか」(句点なし)
「そうか。」(句点あり)
※どちらか一方に統一する
```

---

## 5. 読み仮名のルール

### 5.1 読み仮名の記載方法 🔴
- 読み仮名が必要な語句は、該当語句の直後に全角()で読み仮名を記載する
- **実装難易度**: 高
- **理由**: どの語句に読み仮名が必要か、文脈に応じた読みの判断が必要

**例**:
```
葬(とむら)い
洛中(らくちゆう)
```
